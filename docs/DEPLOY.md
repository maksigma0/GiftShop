# Выкладка на hb.by (тариф «Unix Старт», ISPmanager)

Пошаговая инструкция: от собранного проекта до работающего сайта на своём домене.
SSH на тарифе нет, поэтому всё делается через панель ISPmanager и её файловый менеджер.

> Названия кнопок в панели могут немного отличаться от написанных здесь —
> ориентируйтесь по смыслу. Документация панели:
> [создание Node.js-проекта](https://www.ispmanager.com/docs/ispmanager/creating-a-new-nodejs-project),
> [управление проектом](https://www.ispmanager.com/docs/ispmanager/managing-a-nodejs-project).

## Как это работает

```
Браузер → nginx хостинга (HTTPS, домен) → наше приложение (node server.mjs, порт из PORT)
                                              ├─ build/      — собранный сайт
                                              └─ ../sladkij-mir-data/
                                                   ├─ shop.sqlite  — база
                                                   └─ media/       — фото товаров
```

- Приложение — постоянно работающий процесс. Им управляет менеджер процессов панели.
- Порт выдаёт панель через переменную `PORT`, nginx сам проксирует на него домен.
- База и фото лежат **вне** папки сайта: при обновлении папку сайта можно перезаливать целиком, данные не пострадают.

## Что понадобится

- Логин и пароль от ISPmanager (в письме от hb.by после покупки).
- Домен, купленный вместе с тарифом.
- На своём компьютере: Node.js 22.13 или новее, проект из GitHub.

---

## Шаг 1. Проверить, что домен смотрит на хостинг

1. Если домен куплен в hb.by вместе с хостингом — он обычно привязывается сам.
   Если у другого регистратора — в его панели пропишите NS-серверы hb.by (они есть в письме или в справке hb.by).
2. Проверьте с компьютера (вместо `example.by` — ваш домен):
   ```bash
   nslookup example.by
   ```
   Должен вернуться IP-адрес. Если пишет, что домен не найден, подождите: после смены NS обновление занимает до суток.

## Шаг 2. Придумать секреты для сервера

Нужны **новые** значения, не те, что в локальном `.env`:

- **Пароль админки** — длинный, не короче 16 символов. Сохраните его в менеджере паролей.
- **Секрет сессии** — 64 случайных символа:
  ```bash
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  ```

Никуда их не коммитьте и не пересылайте в мессенджерах.

## Шаг 3. Собрать релиз

```bash
git switch main
git pull
npm ci
npm test
npm run release
```

Появится папка `release/`:

```
release/
├── build/          собранный сайт
├── package.json    без зависимостей — панели нечего устанавливать
└── server.mjs      стартовый файл
```

Заархивируйте **содержимое** папки `release/` (выделить три элемента → «Сжать»), а не саму папку.
Получится `release.zip`, внутри которого сразу лежат `build/`, `package.json`, `server.mjs`.

## Шаг 4. Создать Node.js-сайт в ISPmanager

Откройте раздел **Сайты**.

**Если сайта для домена ещё нет:**

1. **Создать сайт → Node.js-проект**.
2. Заполните:
   - **Имя домена** — ваш домен;
   - **Версия Node.js** — **22.13** (или новее из ветки 22);
   - **Способ подключения** — **Порт**;
   - **Способ создания** — **Загрузить код приложения → С локального компьютера**, выберите `release.zip`.
3. **Создать**. Панель распакует архив и выполнит `npm install` (он пройдёт мгновенно: зависимостей нет).

**Если сайт для домена уже есть** (например, hb.by создал его как PHP-сайт):

1. Выделите сайт → **Изменить**.
2. **Обработчик** — **Node.js**, **версия** — **22.13**, **способ подключения** — **Порт**. Сохраните.
3. Откройте **Менеджер файлов**, зайдите в папку сайта (обычно `www/ваш-домен`), удалите оттуда всё, что положил хостинг (например, `index.html`).
4. Загрузите `release.zip` и распакуйте его прямо в этой папке. В папке сайта должны лежать `build/`, `package.json`, `server.mjs`.

## Шаг 5. Настроить запуск и переменные окружения

Выделите сайт → меню действий → **Настройки запуска (Node.js)**.

1. **Команда запуска** — выберите `start` (это `node server.mjs` из `package.json`).
2. Добавьте **переменные окружения**:

   | Имя | Значение |
   |---|---|
   | `NUXT_ADMIN_PASSWORD` | пароль админки из шага 2 |
   | `NUXT_SESSION_PASSWORD` | секрет сессии из шага 2 |
   | `NUXT_DATA_DIR` | `../sladkij-mir-data` |

   `PORT` добавлять **не нужно** — его задаёт панель.
3. **Сохранить и перезапустить**.
4. В списке сайтов, в колонке **Параметры**, статус должен стать успешным. Если там ошибка — нажмите на неё и посмотрите лог (см. «Если что-то пошло не так»).

## Шаг 6. Включить HTTPS

**Без этого шага не получится войти в админку**: cookie входа на боевом сервере передаётся только по HTTPS.

1. Раздел **SSL-сертификаты** → **Создать** → **Let's Encrypt**.
2. Выберите сайт, отметьте домен и `www.` домен → **Создать**. Выпуск занимает пару минут.
3. В настройках сайта (**Сайты → Изменить**) выберите этот сертификат и включите **перенаправление HTTP на HTTPS**.

## Шаг 7. Проверить и наполнить сайт

1. Откройте `https://ваш-домен/` — главная с фото магазина.
2. `https://ваш-домен/catalog` — каталог пока пустой, это нормально.
3. `https://ваш-домен/admin` — войдите с паролем из шага 2.
4. **Категории → Добавить**: например, «Кондитерские изделия» и «Новогодние подарки».
5. **Товары → Добавить** — с ценой, весом и фото.
6. Проверьте каталог, карточку товара и избранное с телефона.

> Демо-данные с сырами и колбасой на боевой сервер не заливаем — это данные для разработки.

## Обновление сайта

1. Локально: `git pull`, `npm ci`, `npm test`, `npm run release`, заархивировать содержимое `release/`.
2. В **Менеджере файлов** в папке сайта удалите старые `build/`, `package.json`, `server.mjs`.
3. Загрузите и распакуйте новый архив.
4. **Сайты** → выделить сайт → **Перезапустить (Node.js)**.

Папку `sladkij-mir-data/` (уровнем выше папки сайта) **не трогайте никогда**: там база и фото.
Схема базы обновляется сама при старте приложения.

## Резервные копии

- hb.by делает бэкап всей подписки, включая `sladkij-mir-data/`.
- Дополнительно раз в месяц и перед крупными изменениями скачивайте `sladkij-mir-data/` через **Менеджер файлов** (архивом) к себе.

## Если что-то пошло не так

Первым делом: **Сайты** → колонка **Параметры** → нажать на статус → читать лог.

| Что видно | Причина | Что делать |
|---|---|---|
| `502 Bad Gateway` на сайте | приложение не запустилось | открыть лог, искать ошибку ниже |
| В логе `No such built-in module: node:sqlite` | версия Node.js ниже 22.13 | в настройках сайта выбрать 22.13+, перезапустить |
| В логе `Cannot find module …/build/server/index.mjs` | файлы распакованы во вложенную папку | `build/`, `server.mjs`, `package.json` должны лежать прямо в папке сайта |
| При входе в админку `NUXT_SESSION_PASSWORD не задан…` | нет переменной или она короче 32 символов | шаг 5, перезапустить |
| Пароль верный, но админка снова показывает вход | сайт открыт по `http://` | шаг 6 (HTTPS) |
| «Неверный пароль», хотя пароль верный | переменная `NUXT_ADMIN_PASSWORD` с лишним пробелом | вписать заново, перезапустить |
| После обновления пропали товары и фото | `NUXT_DATA_DIR` не задан, и данные лежали в папке сайта | всегда задавать `NUXT_DATA_DIR=../sladkij-mir-data`; восстановить из бэкапа hb.by |
| `npm install` в панели завершился с ошибкой | загружены исходники, а не `release/` | загружать только содержимое `release/` |

Если не помогло — напишите в поддержку hb.by и приложите текст из лога.
